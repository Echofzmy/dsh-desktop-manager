# DSH 桌面实例管理器 设计方案

状态：提案，未实施。本文只描述目标设计与评审点，不承诺任何已实现能力。

## 1. 目标

做一个 macOS 桌面应用，用于管理多个 DSH（DeepSeek Harness）运行版本。

应用提供三件事：打开不同版本 DSH 实例的入口、并行运行多个实例的能力、以及版本切换与回退的控制台。

应用同时是版本管理器：内置一个已验证的官方 DSH 作为兜底运行版本，可以下载并校验更新的官方版本，也可以注册本机任意 DSH 源码目录作为本地运行版本。

应用自身不依赖任何被管理的 DSH 版本。某个 DSH 完全无法启动时，桌面应用仍然可用，仍然可以启动另一个版本去修复它。

Word 只作为“顶部持久导航”的参考；标签页模型参考浏览器与 IDE（可关闭、可拖拽、区分活动实例），不复制 Word 的具体布局，见第 5 节。

## 2. 目录规划

目标目录结构：

```text
/Users/liangyc/Documents/Deepseek-Harness/
├── dsh-v1/            # 本地运行版本 1，例如当前代码
├── dsh-v2/            # 本地运行版本 2，候选修改版
```

应用数据目录位于 macOS Application Support，路径示例为 `~/Library/Application Support/DSH Manager/`。应用数据目录存放下载的官方版本、环境、实例状态、日志与锁，不存放内置官方版本；内置官方版本位于应用 bundle 内（见第 2 节目录结构）。应用数据绝不存放在被管理的运行版本目录内，保证运行版本全部损坏时管理器仍可启动。

## 3. 核心概念

四个概念相互独立，必须分开选择。

运行版本（Runtime）：DSH 代码本体，即某个文件夹里的 dsh 源码或构建产物。来源分为内置官方、已下载官方、本地文件夹三类，见第 6 节。

工作目录（Workspace）：被管理的实例允许 Agent 读取和修改的项目目录。

环境（Environment）：该实例的数据根目录，即 DSH_HOME。存放设置、凭据、Profile、会话、附件。环境分为生产、隔离、快照三类，见第 8 节。

实例（Instance）：一个可运行单元，由一个运行版本、一个工作目录、一个环境、一个端口组合而成。一个运行版本可以同时有多个实例，也可以只有零个。

选择运行版本与选择工作目录必须独立。这支撑自举开发：稳定版本 dsh-v1 以 dsh-v2 为工作目录，负责修改 dsh-v2；同时 dsh-v2 以独立端口和隔离环境启动候选实例用于测试。dsh-v2 完全崩溃时，dsh-v1 实例不受影响，可以继续修复 dsh-v2。

## 4. 功能范围

实例管理：创建、启动、停止、重启、删除实例；为实例打开 GUI；查看启动与运行日志；查看实例状态与端口。

运行版本管理：注册本地运行版本；查看运行版本信息与预检结果；管理内置与已下载官方版本；标记默认运行版本；删除已注册的运行版本。

官方版本更新：从 npm 拉取最新官方版本信息；下载、校验、注册为新的官方运行版本；不覆盖内置兜底版本；不自动改变默认运行版本。

环境管理：创建生产、隔离、快照环境；查看实例使用的环境；防止同一环境被多个实例并发写入。

切换与回退：把实例提升为新的生产默认版本；在提升失败时同时回退运行版本与环境数据。

预检与构建：注册运行版本时执行预检；提供构建、类型检查、测试入口；构建失败阻止启动。

## 5. 页面设计

应用使用固定导航栏与标签页结构。顶部导航栏常驻：Home、新建实例按钮、运行中实例标签、设置入口。新建实例按钮在任何页面都可用。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ● Home │ ＋ New Instance │ ◉ dsh-v1(运行) │ ○ dsh-v2(已停止) │ ⚙ Settings │
└──────────────────────────────────────────────────────────────────────┘
```

导航栏构成固定：Home 与 + New Instance 常驻且不可关闭；每个运行中实例一个标签，带状态圆点（运行/停止/异常）；Settings 固定在最右。

Word 只是“顶部持久导航”的参考，不复制其具体布局。浏览器与 IDE 的标签页模型更贴合本工作流：标签可关闭、可拖拽、区分活动实例、支持后台运行。关闭实例标签只隐藏视图并询问是否保留进程，见 5.3。

标签页对应运行中的实例，嵌入该实例的 DSH Web GUI。未打开的实例不在标签页中，从 Home 打开。

### 5.1 Home 页

Home 是默认页，布局为仪表盘，不做应用启动时的欢迎引导。

```text
┌──────────────────────────────────────────────────────────────────┐
│ ● Home                                                              │
│ ┌──────────────┐ ┌──────────────┐                                  │
│ │ dsh-v1       │ │ dsh-v2       │   运行中实例卡片区                │
│ │ 3080 运行中  │ │ 3081 已停止  │   （停止/重启/打开 GUI/日志）      │
│ └──────────────┘ └──────────────┘                                  │
│ 可用运行版本区           环境区           最近日志区                 │
└──────────────────────────────────────────────────────────────────┘
```

运行中实例卡片区：每张卡片显示实例名、运行版本、工作目录、端口、环境类型、运行状态、最近一次健康检查结果。卡片提供停止、重启、打开 GUI、打开日志操作。

可用运行版本区：列出已注册运行版本与内置官方版本，显示版本号、来源类型、Git commit、工作树是否干净、预检结果。提供新建实例与重新预检操作。

环境区：列出生产环境与隔离环境，显示当前被哪个实例使用，以及最后备份时间。

最近日志区：最近日志条目的简要列表，点击进入日志页。

### 5.2 新建实例

点击顶部新建实例按钮打开新建实例对话框。

表单字段：实例名称、运行版本、工作目录、环境类型、端口。

运行版本选择器列出内置官方、已下载官方、本地文件夹三类来源；本地文件夹来源可直接输入路径或通过目录选择器选择。

工作目录选择器默认指向当前选中运行版本所在目录，可改为任意目录。

环境类型：生产、隔离、快照。隔离环境默认生成唯一环境目录；快照环境需要选择来源环境。生产环境与已运行实例占用的环境不可重复选择。

端口默认自动分配一个未占用的回环端口，可手动覆盖；与运行中实例端口冲突时表单报错。

提交前显示该运行版本的预检结果摘要；预检未通过时禁止启动，允许只注册不启动。

### 5.3 实例标签页

每个运行中实例一个标签页，标签显示实例名与状态圆点。

```text
┌──────────────────────────────────────────────────────────────────┐
│ ◉ dsh-v1 │ 实例工具栏：名称 版本 commit 工作目录 端口 环境 状态     │
│          │ 健康检查 / 重启 / 停止 / 外部浏览器 / 日志              │
│ ┌────────────────────────────────────────────────────────────┐  │
│ │                    嵌入的 DSH Web GUI                      │  │
│ └────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

标签页内容嵌入该实例的 DSH Web GUI。嵌入区域上方是实例工具栏：实例名、运行版本、commit、工作目录、端口、环境、状态、健康检查按钮、重启、停止、打开外部浏览器、打开日志。

关闭实例标签页只隐藏该实例的视图，不终止进程。关闭时询问用户：保留进程在后台继续运行，还是停止进程。标签页关闭绝不静默终止进程；终止只能通过显式的停止操作或管理器退出流程。

GUI 加载失败时标签页显示错误状态与日志入口，不显示空白。

### 5.4 日志页

日志页或抽屉展示选中实例的 stdout、stderr 与健康检查记录。日志支持按时间过滤与搜索。管理器把每个实例的输出追加写入 `logs/<instance-id>/` 下的文件，进程退出后日志仍可查看。

### 5.5 设置页

设置页管理官方版本：显示内置版本、已下载版本列表、检查更新按钮、下载进度、校验结果。提供标记默认运行版本的选项。默认运行版本只影响新建实例的预选值，不自动切换任何运行中实例。

设置页管理应用自身：数据目录路径、自动检查更新开关、打开日志目录。

## 6. 运行版本

### 6.1 内置官方版本

应用安装时内置一份已验证的官方 DSH 构建产物，存放于应用 bundle 内 `Contents/Resources/runtimes/official/bundled/`，只读，随应用签名分发。内置版本在应用打包时生成，并附带该打包对应的 release manifest 与 checksum（见 6.2 与 14）。

内置版本自包含：携带兼容的 Node 运行时与完整的已安装、已构建 DSH 依赖闭包，启动不依赖系统 Node 或 pnpm。

内置版本保证离线或网络故障时仍有一个可运行的官方版本。下载新官方版本不会覆盖内置版本。

### 6.2 已下载官方版本

应用从 npm 查询 `@deepseek-ai/dsh` 最新版本。用户确认后下载对应 tarball，校验后解压到应用数据目录 `runtimes/official/downloaded/<version>/`，注册为只读官方运行版本。

校验不假设上游提供发布签名，按以下信任源执行：
- 仅从固定官方源通过 HTTPS 下载（npm registry 与官方发布页）；
- 校验 npm 元数据中的 `dist.integrity`（存在时）；
- 校验解压后的包名与版本等于期望值；
- 与应用打包时生成的 release manifest/checksum 对比；
- 仅当存在权威签名时才执行签名验证。

校验失败则丢弃下载结果，不注册。下载行为可被用户取消。

多个已下载版本可共存。删除已下载版本需要确认；被运行中实例使用的版本禁止删除。

### 6.3 本地运行版本

用户注册本机任意目录作为本地运行版本，例如 `/Users/liangyc/Documents/Deepseek-Harness/dsh-v1`。

注册时记录：路径、名称、注册时间、Git 远端、当前 commit、工作树是否干净、Node 与 pnpm 版本、依赖是否安装、构建产物是否存在。

工作树脏的目录可以注册，但被标记为稳定版本或用于生产提升的目录应指向已提交 commit，保证回退目标明确。

### 6.4 预检

预检在注册时执行，在每次启动前重跑。预检项：

- 目录存在且是 DSH 源码或构建产物，存在 `apps/cli/lib/bin.js` 或可等效启动入口。
- Node 版本满足引擎要求。
- pnpm 可用且版本匹配锁文件要求。
- `node_modules` 已安装，缺失时提示先执行依赖安装。
- 构建产物存在，缺失时提示先执行构建。
- 目录是 Git 仓库时，记录 commit 与工作树状态。

预检结果为通过、警告、失败三级。失败项列出具体原因与修正动作。预检通过才能启动实例。

### 6.5 启动命令

本地运行版本启动已构建实例的命令：

```text
node <runtime>/apps/cli/lib/bin.js web --port <port> --no-open
```

内置官方版本使用其自带的 Node 运行时与完整依赖闭包，通过 bundle 内入口启动，不依赖系统 Node 与 pnpm。本地运行版本使用系统 Node/pnpm，启动前按第 6.4 节预检其声明的工具链。

工作目录设为实例的工作目录。环境变量 DSH_HOME 设为实例的环境目录。以构建产物启动，不重新构建。

修改过源码的运行版本需要先构建再启动。管理器提供构建入口，构建成功后才能启动。构建失败时禁止启动并展示错误。

## 7. 实例生命周期

启动：检查预检结果；检查端口未占用；检查环境未被其他实例占用；分配日志文件；启动进程；等待 HTTP 就绪。

就绪检查：轮询实例的 Web 端口直到返回成功响应，或超时报错。就绪后才把实例标记为运行中并允许打开 GUI。

停止：先发送 SIGTERM，等待 DSH 的优雅退出窗口（默认至少五秒）。窗口结束后若进程仍在运行，不自动 SIGKILL，而是询问用户：继续等待，还是强制结束。记录退出码与退出原因。

重启：先停止，再按启动流程重新启动。

删除：先停止实例，再删除实例元数据。隔离环境由用户选择是否同时删除；生产环境永不自动删除。

异常退出：进程非预期退出时，实例标记为异常，展示退出码与最近日志，不自动重启。

管理器退出时询问用户：正在运行的实例保留在后台运行，还是随管理器关闭。管理器意外崩溃后，已运行实例作为孤儿进程继续运行，下次启动管理器时检测端口与进程并恢复实例状态标记。

## 8. 环境与数据

DSH_HOME 由管理器通过环境变量注入，实例进程的数据写入范围限于其环境目录；隔离环境位于应用数据目录内，生产环境为用户选择的 `~/.dsh`。

生产环境：默认 `~/.dsh`，与现有使用保持一致。同一时刻只有一个实例可以使用生产环境。

隔离环境：`<应用数据目录>/instances/<instance-id>/home/`，新建实例默认使用。不同实例的环境目录不同，互不共享。

快照环境：创建时从指定来源环境复制一份快照，之后独立演化。快照用于在测试实例中重现生产会话，测试产生的数据不自动合并回生产。

并发规则：管理器禁止两个运行中实例使用同一 DSH_HOME。启动前校验环境占用；重复占用直接拒绝启动。

数据安全：管理器自身不解析会话格式，不做会话迁移。生产提升与回退通过整体备份与恢复环境目录实现，见第 9 节。

## 9. 默认版本、提升与回退

默认版本是新建实例的预选运行版本，不自动切换运行中实例，不自动替换生产环境。

提升流程：候选实例在隔离端口与隔离环境中完成构建、启动、就绪检查，并由用户实际发起一次测试对话；停止生产实例；备份生产环境；用候选运行版本启动生产实例；确认启动与对话正常；把候选运行版本记录为新的默认版本；保留上一运行版本与备份。

回退流程：停止故障实例；把故障后的环境目录移到诊断目录；恢复备份的生产环境；用上一运行版本启动生产实例；确认恢复正常。回退同时恢复运行版本与环境，因为仅回退代码可能遇到新版已升级的数据格式。

提升与回退的记录写入应用数据目录，包含时间、运行版本、commit、环境备份路径、结果。

## 10. 技术方案

桌面框架选用 Electron。DSH 与桌面应用同为 TypeScript 与 Node.js 生态，主进程可直接使用 child_process 管理 DSH 子进程，读取 Git、Node、pnpm、端口状态。嵌入式多实例 Web GUI 用 Electron WebContents 承载。Tauri 更轻但需维护 Rust 进程管理层，作为后续评估项。

主进程：运行版本注册与预检、实例进程管理、端口分配、环境占用校验、官方版本下载校验、日志写入、设置持久化。

预加载脚本：通过 contextBridge 暴露窄 IPC 接口。接口只包含管理器功能所需命令：实例列表、启动停止重启、日志读取、运行版本注册、预检、官方版本操作、设置读写。不允许 DSH 页面调用任意进程能力。

渲染进程：React 实现第 5 节页面。

WebContents 安全配置：nodeIntegration 关闭，contextIsolation 开启；限制页面只能导航到 127.0.0.1 的受管端口；实例页面与管理器 IPC 隔离；不向 DSH 页面注入 Node 能力。DSH 自身只绑定回环地址，管理器不自动开放 LAN 端口。

凭据策略：DEEPSEEK_API_KEY 与 provider 凭据由用户放入环境（环境变量或 DSH_HOME 内文件），管理器不读取、不存储、不展示凭据值。官方版本下载校验使用固定官方源 HTTPS、npm dist.integrity、release manifest/checksum，以及存在时的权威签名，不涉及用户凭据。

## 11. 迁移方案

当前目录 `/Users/liangyc/Documents/dsh` 在迁移后成为 `/Users/liangyc/Documents/Deepseek-Harness/dsh-v1`。

迁移步骤：先确认当前 3080 实例已停止或已明确由谁接管；创建顶层目录 `/Users/liangyc/Documents/Deepseek-Harness`；将当前 checkout 移动到其 `dsh-v1` 子目录；以后新版本按 `dsh-v2` 命名放入同一顶层目录；在桌面应用中把 `dsh-v1` 注册为本地运行版本；生产环境继续使用 `~/.dsh`。

移动 checkout 后需要重跑仓库的 hook 与依赖安装设置（例如 `node scripts/install-lefthook.mjs` 或重新 `pnpm install`），因为 hook 路径等工作区路径可能指向旧位置。

目录改名影响当前实例的工作目录路径。执行迁移前需要停止引用旧路径的实例。管理器源码与应用的目录规划不属于迁移目标，见第 2 节。

## 12. MVP 阶段

第一阶段：实例管理基础。注册本地运行版本，预检，创建实例，启动停止重启，端口分配，隔离环境，嵌入 GUI，日志查看。内置官方版本随应用提供。

第二阶段：官方版本更新。检查更新、下载、校验、注册已下载官方版本。

第三阶段：开发能力。展示 Git 状态与 commit，执行依赖安装、类型检查、选择测试、构建，启动前预检门禁。

第四阶段：提升与回退。生产提升流程、环境备份、代码与数据回退、默认版本语义。

第五阶段：增强。Git worktree 管理、自动创建版本目录、菜单栏控制、管理器自动更新、实例模板。

## 13. 非目标

本设计不做以下事项：插件安装与插件市场；移动端应用；多设备同步；DSH 核心功能开发；会话内容迁移工具；局域网开放；通用 CI 与测试编排产品。管理器在第三阶段可调用所选仓库的测试命令，但测试编排与自动化测试套件不属于本设计范围。
